# MTrack — архитектура

Проект продолжает исходную Java / Views архитектуру без переписывания на Kotlin. Android API 26–35, Material 3, Room 2.6.1, AGP 8.7.3, Gradle 8.11.1 и JDK 17.

## Потоки и состояние

`MainActivity` строит экраны из снимков Room. Пока Activity видима, она запрашивает обновления раз в секунду. Навигация и выбранная запись сохраняются через savedInstanceState. Activity не владеет состоянием тренировки и не останавливает сервис при пересоздании.

`Store.IO` — общая очередь HandlerThread для команд сервиса, GPS-callbacks, чтения и записи базы. В UI-потоке запросов Room нет. Отсутствуют гонки между checkpoints, паузой, удалением и экспортом. Сохранение точки и метрик атомарно.

`TrackingService` живёт отдельно от экрана и использует системный LocationManager. Google Play Services и сетевые SDK не нужны. Сервис хранит checkpoint каждую секунду. Восстановление сервиса загружает незавершённую тренировку на паузе. Возобновление записи требует действия пользователя. Завершить восстановленную тренировку можно и без новой геолокации.

## Данные

Room v3: `ActivitySession` (1:N) `ActivityPoint`, локальные профиль и настройки. `endedAt=0` обозначает незавершённую запись. `paused` хранит паузу; `liked` и `savedRoute` — только локальные действия. `ActivityPoint.segment` отделяет точки до и после паузы; разрывы времени дополнительно проверяются расчётами. Индекс по `sessionId` ускоряет чтение маршрута.

Миграция 2→3 добавляет поля и индекс без потери данных. Destructive migration отключена. Удаление тренировки и её точек выполняется транзакционно. Сущности целей / сегментов исходного проекта сохранены для совместимости базы, но не выданы за готовые функции UI.

## Метрики и представление

`ActiveClock` считает длительность по монотонному времени и исключает ручные паузы. `TrackMetrics` не зависит от Android API, использует Haversine и фильтрацию координат. Все значения в хранилище: метры, миллисекунды, км/ч; настройки единиц влияют только на представление.

`RouteView` рисует только реальные принятые точки, без внешнего провайдера карты. График прогресса строится из завершённых записей текущей календарной недели / месяца. Экспорт JSON содержит исходные координаты и требует явного действия пользователя.

Тесты и инструкции запуска описаны в README. Перед релизом требуется физическое тестирование длительной фоновой записи и поведения разрешений на актуальном Android.
