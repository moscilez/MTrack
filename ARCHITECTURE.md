# MTrack — архитектура этапа 1

## Слои

- `data`: Room entities и DAO; база полностью локальная.
- `tracking`: Foreground Service и будущий координатор GPS-потоков.
- `presentation`: текущий программный UI в `MainActivity`; следующий шаг — вынести экраны в отдельные ViewModel/Fragment-компоненты.

## Схема данных

`UserProfile (1)` — локальный профиль.

`ActivitySession (1:N ActivityPoint)` — сессия с типом, временем и агрегированными метриками.

В следующих миграциях добавляются `ActivitySegment`, `ActivityStatistic`, `Goal`, `GoalProgress`, `UserSettings`, `ExportMetadata` и индексы по времени/сессии.

## Навигация MVP

`Dashboard → Start activity → Recording → Dashboard`

Нижняя навигация: `Dashboard / History / Profile`.

## Принятые решения

- Java остаётся основным языком.
- Карта не является обязательной частью MVP: сначала сохраняются координаты и маршрутная модель, затем подключается заменяемый `MapProvider`.
- Разрешения запрашиваются при запуске трекинга, а не на первом экране.
- Для автомобильного режима используется тот же безопасный минимальный экран записи; приложение не является сертифицированным спидометром.

## Риски и следующий этап

Нужно завершить порционную запись `ActivityPoint`, фильтрацию GPS-скачков, расчёт метрик, шифрованный экспорт/импорт, QR-перенос, локальные рекомендации и instrumentation-тесты.
