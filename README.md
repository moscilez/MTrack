# MTrack

Локальный спортивный трекер для Android 8.0+ (API 26). Сохранён исходный стек проекта: **Java 17, Android Views / Material 3, Room и foreground location service**. Сервер, аккаунт и ключи не нужны.

## Что работает

- Русский интерфейс: главная со сводкой за календарную неделю, история, прогресс и профиль в нижней навигации.
- Бег, ходьба и велосипед. Живой таймер, дистанция, средний темп или скорость, GPS-статус, схема фактического маршрута.
- Ручная пауза, продолжение, завершение с подтверждением, итоговый экран. Системный Back предлагает оставить запись в фоне.
- Запись в foreground service с уведомлением и кнопкой паузы / продолжения. Открытие уведомления возвращает к тренировке.
- Сохранение точек и метрик в Room, история с фильтрами и удалением с подтверждением. Миграция существующей базы версии 2 в 3 сохраняет записи.
- Прогресс за календарную неделю / месяц: дистанция, время, число тренировок, диаграмма по дням и численные значения. Незавершённая тренировка в статистику не входит.
- Локальная лента собственных тренировок и сохраняемые реакции. Маршрут можно добавить в «Мои маршруты», открыть и начать новую активность того же вида. Пошаговой навигации нет.
- Локальное имя, километры / мили (включая темп и скорость), тёмная / светлая / системная тема.
- Экспорт завершённых данных с координатами в JSON через системный выбор файла. Удаление отдельных тренировок и всех данных с подтверждением. Управление данными требует завершить активную запись.

Интерфейс использует тёплый тёмный фон, тонкие границы, светлый текст, моноширинные показатели и сдержанный зелёный акцент. Общая атмосфера учитывает [opencode.ai](https://opencode.ai/); фирменные элементы и экраны других продуктов не копируются.

## Требования и сборка

- JDK **17** (`JAVA_HOME`), Android SDK Platform **35**, Build Tools **34.0.0** (по умолчанию для используемого AGP), Platform Tools.
- Android Studio с поддержкой AGP **8.7.3** или командная строка. Gradle **8.11.1** уже указан в wrapper.
- Интернет для первого скачивания зависимостей Gradle. Во время работы приложению интернет не требуется; разрешения `INTERNET` в манифесте нет.
- Создай локальный `local.properties` (не коммитить), например: `sdk.dir=C:/Users/yourname/AppData/Local/Android/Sdk`. На macOS/Linux укажи свой путь к SDK.

Windows / PowerShell:

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat testDebugUnitTest lintDebug
```

macOS / Linux:

```sh
chmod +x gradlew
./gradlew assembleDebug testDebugUnitTest lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Debug-сборка подписывается стандартным локальным debug-ключом Android. Для распространения релиза настрой собственную подпись вне репозитория.

Подключи телефон с USB debugging и подтверди доверие компьютеру:

```powershell
adb devices
.\gradlew.bat installDebug
adb shell am start -n com.moscilez.track/.MainActivity
```

Либо открой проект в Android Studio, выбери устройство и нажми Run. Первый сценарий: **Начать тренировку → вид спорта → точная геолокация → запись → Завершить и сохранить → история**. Для реального GPS выйди на улицу. В помещении таймер работает, но маршрут и темп могут оставаться неизвестными (`—`).

## Разрешения и фон

- `ACCESS_FINE_LOCATION` и `ACCESS_COARSE_LOCATION` запрашиваются вместе, только при старте. Для спортивных метрик требуется **точная** геолокация; приблизительный доступ объясняется как недостаточный. При отказе доступны повторный запрос и переход в настройки приложения.
- На Android 13+ перед стартом объясняется и запрашивается `POST_NOTIFICATIONS`. Отказ не блокирует запись: вернуться к ней можно с главной. Android может скрывать уведомление из обычной шторки при отказе.
- Объявлены `FOREGROUND_SERVICE` и `FOREGROUND_SERVICE_LOCATION`, тип сервиса — `location`. Сервис создаётся из видимого приложения после разрешения геолокации. Постоянный доступ `ACCESS_BACKGROUND_LOCATION` не запрашивается. См. [требования Android к location service](https://developer.android.com/develop/background-work/services/fgs/service-types#location).
- Если геолокация отключена, приложение предлагает настройки устройства. При потере сигнала время записи продолжает идти, но отсутствующие координаты не придумываются.
- Сервис не зависит от Activity: сворачивание и её пересоздание не завершают запись. Прошивка телефона всё же может ограничивать работу сервисов; длительную запись с выключенным экраном нужно проверить на конкретном устройстве. Если производитель ограничивает приложение, разреши ему фоновую работу в системных настройках батареи.
- При завершении процесса запись остаётся в базе. При следующем открытии она доступна **на паузе**, с возможностью продолжить или сохранить. Неизвестный промежуток после последнего checkpoint не включается во время. Принудительная остановка приложения и перезагрузка телефона не запускают GPS автоматически.

## Расчёт метрик и устойчивость

`ActiveClock` использует `elapsedRealtime`, а не изменяемые часы телефона. Ручные паузы исключаются из длительности; ожидание GPS и остановки без нажатия «Пауза» входят во время записи. Автоматическая пауза не заявлена и не включена.

Принятые координаты и агрегаты сохраняются одной транзакцией; таймер обновляется в базе каждую секунду. При аварийном завершении может не сохраниться последний интервал до checkpoint. Ошибка записи приостанавливает тренировку и показывает сообщение; после освобождения памяти можно продолжить или повторить сохранение.

Фильтр отбрасывает устаревшие fixes старше 15 секунд, точность хуже 40 м, невалидные координаты, повторные timestamps, малое дрожание GPS и неправдоподобные скорости (12 м/с для бега / ходьбы, 30 м/с для велосипеда). После паузы или разрыва более 30 секунд новая точка становится началом отдельного отрезка. Дистанция не считается между такими отрезками. Максимальная скорость рассчитывается из принятых отрезков; средний темп / скорость — из дистанции и активного времени.

Калории, пульс и набор высоты не показываются: надёжного источника этих данных нет. Неизвестная дистанция / темп показываются как `—`. Числа в прогрессе получаются исключительно из сохранённых завершённых тренировок.

## Маршрут и карты

Используется `ui/RouteView`: **схема полученных GPS-точек без картографической подложки**, явно подписанная в UI. Нет вымышленных улиц, тестовых маршрутов, запросов тайлов или необходимости API-ключа. Круг обозначает начало, квадрат — финиш. Разрывы GPS и паузы не соединяются линией. Всё работает без интернета и Google Play Services (координаты получает системный `LocationManager`).

Для текущей сборки **внешняя настройка не нужна**. Для будущей полноценной карты потребуется отдельно подключить провайдер (например, MapLibre с лицензированным стилем/тайлами), соблюдать атрибуцию и лимиты сервиса и добавить `INTERNET`, если тайлы сетевые. При выборе сервиса с ключом передавай его из локального Gradle property / CI secret; не добавляй ключ в исходники. Оставь эту схему как fallback при отсутствии конфигурации и сети. Публикация, облачная синхронизация и общая социальная лента сейчас отсутствуют и не изображаются работающими.

## Логотип

Найден и сохранён оригинал: **`app/src/main/res/drawable/mtrack_logo.png`**. Он используется в шапке главной и foreground-слое adaptive launcher icon. Исходник не растянут и не изменён.

Подготовлены:

- `res/mipmap-mdpi` … `mipmap-xxxhdpi/ic_launcher.png` — размеры 48/72/96/144/192 px;
- `res/mipmap-anydpi-v26/ic_launcher.xml` — адаптивная иконка с белым фоном и исходным логотипом;
- `res/mipmap-anydpi-v33/ic_launcher.xml` и `res/drawable-nodpi/ic_launcher_monochrome.png` — тематическая иконка Android 13+ на основе силуэта логотипа;
- `res/drawable/ic_tracking.xml` — отдельный одноцветный системный индикатор записи для уведомления (launcher bitmap для статус-бара не подходит).

Если заменишь логотип, положи новый файл по тому же пути, сохрани пропорции и достаточные поля для маски adaptive icon. Затем на Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Generate-Icons.ps1
```

Генератор центрирует изображение, сохраняет пропорции и строит маску силуэта для системной тематической иконки. Все готовые ресурсы уже включены; запуск генератора для обычной сборки не нужен.

## Приватность и структура

Нет серверной части, рекламы, аналитики или скрытой передачи координат. Бэкапы и перенос приватных данных Android отключены (`allowBackup=false`, `data_extraction_rules.xml`). Экспорт производится только после предупреждения о координатах; выбранный пользователем файл остаётся вне приложения и не удаляется командой «Удалить все мои данные».

- `MainActivity` — экраны, навигация, запросы разрешений, отображение снимков базы.
- `data/Store` — единая последовательная очередь IO; Room не разрешает запросы на главном потоке.
- `data/MTrackDatabase` — Room v3, миграция, транзакционное удаление.
- `tracking/TrackingService` — координаты, команды записи, уведомление, checkpoints.
- `domain` — чистые расчёты времени и спортивных метрик.
- `ui/RouteView` — офлайн-схема маршрута.
- `res/values/strings.xml` — русский UI; для другого языка добавь `values-<language>/strings.xml`.

Оставлены совместимые сущности исходного проекта (`Goal`, `ActivitySegment`), но UI не обещает не реализованные цели и рекомендации. Обновление со схемы v2 поддерживается без сброса. Для более старых неизвестных схем нет destructive fallback: приложение выдаст ошибку чтения вместо молчаливого удаления тренировок.
